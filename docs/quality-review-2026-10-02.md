## 框架与实现判断

应用使用 Next.js App Router、React 客户端工作台、Supabase Auth/Postgres/Storage、Route Handlers 和 Base UI。桌面浏览器定位与现有 ADR 一致。本次未安装缺失的测试工具，使用现有 Python Playwright、Chromium、Vitest、TypeScript、ESLint 和 npm。

原有领域工具已有一定测试基础：重复日程、跨日时间、任务、项目打卡、花销和执行统计均有独立模块。主要风险集中在工作台直接承担同步生命周期、整行 JSON 数据写入、无账号归属的本机记录，以及成功/失败状态与真实保存结果脱节。

同步逻辑现已提取到 `useScheduleSync`，三方合并和本机持久化分别放在 `schedule-merge`、`schedule-persistence`。UI 仍沿用既有领域结构，避免在验收期间同时重写整套状态管理。

## 仍未解决或未验证

1. **真实服务验收尚缺**：真实邮箱登录、远端 RLS 策略、迁移是否全部执行、图片上传/删除、真实 AI 流式响应和计费没有实测。模拟服务不能证明这些远端配置正确。
2. **大型组件债务**：日志写入与同步已从工作台分离；周历和任务控制台仍较大，继续按事件编辑、模板和任务分组拆分属于后续结构改进，不等同于本轮已复现功能缺陷。
3. **旧客户端协议**：整行 JSON 的条件写入仍依赖客户端遵守版本协议；旧版应用的无条件写入需要远端数据库升级策略才能彻底阻止。新版本浏览器的本机协调已补上 IndexedDB 回退。
4. **跨服务边界**：数据库与 Storage 不存在同一事务。本轮已修复删除顺序、重试幂等与破图风险；用户放弃提交状态不确定的上传后，可能遗留孤立对象，需后续服务端回收，不能冒险自动删除正在重试的图片。
5. **本机数据和旧记录归属**：速记、聊天、周报、模板与专注记录仍不承诺跨设备同步。旧版无账号归属的数据未删除、不自动迁移，需要用户确认归属后导入。
6. **部署配置**：AI cookie 现在为加密数据，仍不是服务端凭据库；生产部署须配置同一服务端保护密钥。真实服务的权限和上传仍受第 1 项验收条件限制。

这些边界不影响已列出的隔离核心流程结果，但不应据此声称真实云端环境已经全部验收。
